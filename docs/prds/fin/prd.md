# 财务系统 PRD（fin）

> 本文档定义 WBME 企业管理平台**财务系统**的需求。
> 平台级通用机制（功能权限、统一审批、软删除、金额精度、基础设施、前端规范等）见主 PRD：`docs/prds/prd.md`。

---

## 1. 功能权限清单

> 目录按「系统 → 业务板块 → 功能」三层组织；授权机制、数据范围语义与申请类/审批类功能通用规则见主 PRD §2.5、§3.1。

| 系统 | 业务板块 | 功能 | 可选数据范围 | 说明 |
| --- | --- | --- | --- | --- |
| fin | 合同与利润 | 财务数据查看 | 公司 | 项目、工程合同、利润分析与项目操作记录只读；仅利润分析页支持按指定模板导出（财务查看人员） |
| fin | 合同与利润 | 财务数据维护 | 公司 | 项目新建编辑、财务数据与明细维护、利润分析模板导入；隐含包含“财务数据查看”的全部能力（财务维护人员） |

## 2. 面向用户

财务查看人员（财务数据查看：只读/导出）、财务维护人员（财务数据维护：新建、编辑项目与财务数据）、财务管理员（维护字典与设置）。功能授权与权限组由持有平台"权限管理"功能的人员统一管理（见 backstage PRD §4）。财务数据均为全公司范围，无部门/本人维度。

- 项目列表按项目名称、甲方、年度、地区、业务分类和进度筛选分页查看；详情查看完整合同资料及相关利润数据入口。
- 项目名称保留原文展示，另生成业务键：执行 Unicode NFC 规范化、首尾去空白、连续空白归一化和拉丁字母大小写折叠，再与年度建立数据库唯一约束；导入匹配和页面新建/编辑使用完全相同的规范化规则。项目名称和年度均允许在页面中像其它普通项目字段一样随时修改，保存时只校验新业务键不与其它未删除或软删除项目冲突；不建立旧业务键别名、不锁定字段，也不增加特殊确认或特殊身份变更审计。修改成功后旧名称/年度立即不再用于后续 Excel 匹配，旧导入表可能被识别为新增属于可接受结果；该普通字段修改仍按全站既有主 PRD §3.3 操作日志和 §5 项目操作记录规则记录。软删除记录仍占用其当前业务唯一键，遇到同键时必须提示进入“已删除项目”视图恢复或改名，不能创建无法区分的新记录。
- 新建项目可先录入合同资料，财务数据后续补充；编辑修改合同信息与分类，变更留下操作记录。
- 工程合同页展示“项目名称 → 暂定/审定金额”的连续字段范围；财务维护人员可编辑其中非自动字段。与利润分析页重叠的主合同付款节点、暂定/审定金额直接读写同一项目主记录，不复制数据、不建立额外“维护页面”归属字段。
- 删除按主 PRD §2.6 进行可追溯的批量软删除，删除后不进入正常列表、筛选、统计和导出；提交前校验全部项目，任一项目不可删除则整批回滚并返回失败明细。“财务数据维护”页面提供正常/已删除状态视图，已删除视图只提供勾选后的批量恢复，不提供单条恢复；恢复保留原项目 ID、业务键、合同/利润数据和操作历史，并在一个事务中校验全部目标后全量恢复，任一目标状态或依赖不合法则整批不变更。Excel 导入命中软删除项目仍只提示冲突并引导到该视图，不得把导入覆盖当作恢复。
- 工程合同页不提供 Excel 导入或导出入口。
- 除项目名称和年度外的文本与日期可留空；页面新建或编辑项目时年度不得清空。非自动计算的金额字段默认空白，界面保留“未填写”状态，参与公式时按 0 计算；自动计算的金额字段默认显示 0。所有手工输入的合同金额、暂定/审定金额、开票、收款、分包结算、分包付款和零星费用均必须大于等于 0，允许填写 0，不允许用负数表达冲销；“剩余未开票”“剩余未收款”和“暂定保通权益”等自动计算结果仍保留可能出现的真实负数。金额以元为单位保留两位小数；“暂定/审定金额”的当前语义取项目进度字典项的结构化金额语义，未选择项目进度时按“暂定”处理，不通过进度名称包含“已审结”等文字规则猜测。
- 本节全部金额字段与自动金额遵循主 PRD §9.11：数据库使用 `numeric(18,2)`，后端和导入导出使用十进制定点类型，不使用 JavaScript 二进制浮点数计算；毛利率以高精度十进制完成除法，内部值 `0.25` 在 Web 与 Excel 中统一显示为 `25.00%`。
- 项目进度的 MVP 初始金额语义固定为：`AUDITED（审定）` = “已审结未满质保期、已审结已满质保期未结清、总包结清、项目已结清”；`TENTATIVE（暂定）` = “未开工、已开工未竣工、已竣工未审结、无需审计、暂定”。未选择项目进度时仍按 `TENTATIVE` 处理。

## 4. 利润分析汇总

- 按项目展示**项目名称（只读）+“主合同付款节点 → 毛利率”**的连续字段范围；财务维护人员可像使用工作表一样编辑其中非自动字段。工程合同页与利润分析页的重叠字段读写同一项目主记录并实时同步。
- **单元格即时保存**：项目级可编辑字段进入编辑态后，用户按 Enter/Tab、点击其它单元格或使编辑器失焦即确认本次编辑并立即保存；按 Esc 放弃本次未提交内容。保存不是逐按键发送，也不提交整行或整个项目：每个请求只携带项目标识、一个服务端白名单字段及其新值和幂等键，服务端拒绝同时出现多个业务字段，只在事务中覆盖该字段并记录该字段的前后值。金额明细的新增、修改和删除继续使用各自明细接口，每次只变更一条明细。
- **键盘导航**：编辑态下方向键在单元格间移动焦点，Enter 确认并移动到下方单元格，Tab 横向移动，Esc 取消本次编辑并恢复原值；连续录入无需鼠标。
- **保存状态与失败恢复**：单元格显示“保存中 / 已保存 / 保存失败”状态；请求成功后用服务端返回值和重新计算的自动字段刷新当前行。失败时保留用户刚输入的值并提供重试或恢复服务器值，不静默丢弃，也不把其它单元格回滚。相同单元格的连续保存按发起顺序串行处理，不同单元格可以并行保存。每次成功变更都在事务中递增项目的内部 `dataRevision`，响应携带该值；前端只应用不低于当前行修订号的响应，避免并行请求乱序时用旧汇总覆盖新汇总。对于这里的单字段即时保存，`dataRevision` 只用于响应排序，不作为保存前置条件，不产生版本冲突或 `409`；§4 下述 Excel 全量覆盖因会同时改写多个字段和金额明细，明确作为例外使用预览时的 `dataRevision` 防止覆盖预览后的他人修改。
- **离开保护**：存在保存中或保存失败的编辑时，翻页、改变筛选、切换工作视图、返回、刷新或关闭页面均不得无提示离开。站内跳转使用统一确认框展示未完成数量，并提供”留在本页处理”和”放弃未保存内容并离开”；保存中的请求先等待正常完成，超过请求超时后转为保存失败再由用户决定。浏览器刷新、关闭标签页或关闭窗口使用浏览器原生离开确认，不依赖 `sendBeacon` 或后台请求假装保存成功。
- **撤销与重做**：提供 Ctrl+Z / Ctrl+Y（macOS 为 ⌘Z / ⌘⇧Z，并提供工具栏按钮）撤销/重做已保存成功的编辑。撤销栈保存每次成功编辑的字段、编辑前值与编辑后值，最多保留最近 50 次；撤销按倒序对相应字段重新提交编辑前值，重做重新提交编辑后值（均使用新的幂等键，视为新编辑并继续遵守即时保存规则），新编辑提交后清空重做栈。撤销只覆盖数据编辑，不追踪排序、筛选、列布局等视图变化。
- **轻量并发语义**：本期不要求编辑者携带整项目版本，也不因其它字段被别人修改而拒绝保存；数据库更新语句只写目标字段，因此两人同时编辑不同字段互不覆盖。同一项目的同一字段被多人同时编辑时，以数据库最后成功提交的值为准，不增加锁定、签出或人工合并流程。自动计算字段始终由后端基于事务提交后的最新数据库数据重新计算，不能由某次请求携带的旧整行数据覆盖。
- **计算指标**（由基础数据实时计算，不得手工修改）：累计开票（开票金额求和）、累计收款（已收回款求和）、剩余未开票（暂定/审定金额 − 累计开票）、剩余未收款（暂定/审定金额 − 累计收款）、累计分包付款（零星费用 + 已付分包款求和）、暂定保通权益（累计收款 − 累计分包付款）、毛利率（暂定保通权益 ÷ 累计收款，收款为零显示“—”）。自动计算金额默认 0；非自动金额未填写时界面保持空白、公式按 0 参与计算。“剩余未开票”和“剩余未收款”小于 0 时保留真实负数，不截断为 0；Web 列表、详情、总计和 Excel 中均以红色文字提示，汇总仍按真实负数计算。
- 分析列表按项目、年度、地区、业务分类和进度筛选；页面的**总计**一栏汇总当前筛选结果（不受当前页分页影响），随筛选条件实时计算（如按业务分类筛选时，总计即为该类目的汇总）；页面不额外展示项目小计或分类小计，Excel 导出仍按模板生成分组小计行。
- 金额明细可新增、修改；删除是主 PRD §2.6 明确允许的单条物理删除例外，界面在明细行提供删除入口并二次确认，成功后不可恢复。金额以元为单位展示两位小数；毛利率按百分比展示两位小数，例如内部比率 `0.25` 展示为 `25.00%`。
- **Excel 导入/导出基线**：利润分析页提供 Excel 导入与导出；工程合同与利润分析的项目级字段合并去重后输出。MVP 使用模板版本 V2：`docs/references/工程合同与利润分析.xlsx` 是不含任何项目样例值和样例公式的**空白运行模板**，其工作表名称固定为“利润分析汇总”，标题为“工程合同结算情况及利润分析汇总表”；运行模板负责标题、表头、合并、列宽、行高、字体、底色、边框和数字格式等静态结构。绿色业务分类行、项目数据行、分类小计行及语义色等动态行样式由导出模块中的集中、版本化样式常量生成，不声称从不存在的空白项目行复制样式；样式常量版本必须与模板版本绑定，并使用固定输入的工作簿渲染/结构快照测试防止无意走样。`docs/references/工程合同与利润分析-样例参考.xlsx` 仅供产品与开发人员核对原始视觉、分组和内容形态，不允许被导入/导出程序作为运行模板或样式来源读取，样例中的标题文字、标题年度、工作表名称和项目年度分布均不构成接口或校验规则。两者均已包含本 PRD 要求的“备注”列、统一表头底色和毛利率格式；后续运行模板或动态样式变更必须显式升级同一版本，不允许开发者自行增删列或调整顺序。
- **固定列顺序**：单工作表使用 28 列，依次为“序号、项目名称、资料齐全度、年度、地区、项目进度、甲方、总包方、管理费、分包方、合同开始日期、合同完工日期、合同金额（元）、主合同付款节点、暂定审定金额、开票金额（元）、已收回款（元）、累计开票（元）、累计收款（元）、备注、剩余未开票（元）、剩余未收款（元）、分包结算（元）、已付分包款（元）、零星费用、累计分包付款（元）、暂定保通权益、毛利率”。领域字段“暂定/审定金额”在 Excel 中固定映射为“暂定审定金额”；“备注”是项目级备注，不是金额明细备注。
- **多值单元格往返规则**：资料齐全度、分包方、开票金额、已收回款和已付分包款均使用单元格内换行 `LF` 作为唯一数组分隔符，导出时每个数组项占一行并启用自动换行，顺序与数据库数组/明细顺序一致；导入先把 `CRLF/CR` 规范化为 `LF`，再按换行拆分、去除每项首尾空白并忽略纯空行。逗号、顿号、分号和项目符号均视为某一项内部的普通文字，不作为隐式分隔符，避免把分包方名称、比例说明或其它自由文本误拆；样例参考文件中不一致的逗号/编号写法不构成解析规则。资料齐全度拆分后每项必须精确匹配可导入字典项且不得重复，“可导入”包含下述仅用于原引用往返的停用项例外；分包方保留用户文字和顺序，规范化后完全相同的重复项拒绝导入并指出行号。三类金额每一行必须是独立的非负十进制金额，不接受单位、千分位文字或表达式，空单元格表示空数组；导出使用数值语义与两位小数显示，导入后按原顺序重建明细，因此平台导出的 V2 文件可无歧义重新导入。
- **结构、年度与分组**：导入和导出始终使用**一个工作表**，不按年度拆分；同一工作表可以同时包含 2021、2022 等不同年度项目。项目主记录仍以自身“年度”作为业务事实并与项目名称共同构成业务唯一键，但为兼容历史文件，Excel 项目行的年度允许为空，具体匹配与新增规则见下文。业务分类允许为空；Excel 为保持统一分组结构，把空分类项目放在系统虚拟分组“未分类”下，该分组只表示数据库分类字段为空，不创建真实字典项。导入遇到该系统虚拟分组时映射为空分类，导出时统一放在所有真实分类之后并生成自己的分类小计；财务配置不得创建名称规范化后等于“未分类”的真实业务分类，避免往返歧义。第 1 行为跨 28 列标题，导出固定写“工程合同结算情况及利润分析汇总表”；导入时第 1 行标题文字和工作表名称均不参与模板识别，也不要求包含或匹配年度。第 2 行为上述固定表头（包括模板中的换行、列宽、行高、字体、底色、边框、合并和数字格式），之后由导出服务按与 V2 模板绑定的集中样式常量生成绿色业务分类分组行、项目数据行和分类小计行；业务分类不另占一列，而由分组行上下文导入/导出。导出文件的工作表名称固定为“利润分析汇总”，不得复制样例参考文件中的年度标题、年度工作表名称、项目名称或其它业务值。
- **表头与语义配色**：参考表中原为黄色的“项目进度、管理费、剩余未开票、剩余未收款”等表头改用与相邻普通表头相同的蓝色，其它表头样式保持模板基线，不做无关重绘。颜色区分只应用于每条项目数据行的“暂定审定金额”单元格：金额语义为“暂定”时使用浅黄色，语义为“审定”时使用浅绿色；Web 页面与 Excel 导出保持一致，并同时通过可访问文本/提示和同一行的项目进度表达语义，不能只靠颜色。“剩余未开票”和“剩余未收款”的负数使用红色文字，非负数沿用普通文字颜色。
- **导出规则**：只提供“导出所有 / 导出已筛选”两种数据范围，不提供“导出当前页”。“导出所有”忽略页面筛选和分页，导出当前用户权限范围内全部未逻辑删除项目；“导出已筛选”导出符合当前筛选条件的全部未逻辑删除项目，同样不受当前页分页影响。两种范围均使用同一模板，并固定按“真实业务分类配置顺序 → 虚拟未分类分组最后 → 年度升序 → 项目 ID 升序”稳定排序；项目 ID 是同分类同年度内的最终唯一顺序键，不依赖数据库未声明顺序。序号按导出结果重排，小计只汇总对应范围内数据。系统生成自动计算列和小计公式，用户文本以普通单元格值写入，不能被解释为公式；开票金额、已收回款、已付分包款存在多笔时在单元格内按明细顺序换行展示。毛利率单元格保存数值比率（如 `0.25`）并应用 `0.00%` 数字格式，不写成文本 `25.00%` 或数值 `25`。
- **导出传输**：导出由当前 HTTP 请求以非阻塞 I/O 即时生成并以附件响应直接触发浏览器下载，不上传 OSS，不在 PostgreSQL、Redis 或服务器磁盘保存导出文件，也不创建可再次下载的历史文件。上传读取与下载输出必须处理流背压；解析和序列化等 CPU 密集步骤按主 PRD §9.1 交给有界 Worker Threads 工作池，而不是 BullMQ。响应中断或生成失败时不留下文件，用户可重新发起；导出受最大行数、单用户并发和 120 秒总超时约束，超出行数上限时明确提示缩小筛选范围。
- **导入匹配与空年度兼容**：项目名称在每个项目数据行中始终必填。Excel 行提供年度时，必须先校验为 §3 规定的 `1000～9999` 四位整数，再使用“规范化项目名称 + 年度”精确匹配业务唯一键；未匹配时可作为新增，命中未删除项目时进入“覆盖/跳过”选择，命中软删除项目时标记冲突且不自动恢复或新建。Excel 行未提供年度时，不猜测当前年份，也不允许新增：服务端按规范化项目名称同时检查未删除和软删除记录；恰好只有一条未删除记录且不存在其它同名年度记录时，才把该行匹配到这条现有项目；没有任何同名记录时返回 `VALIDATION + IMPORT_YEAR_REQUIRED_FOR_NEW`，存在多条同名跨年度记录时返回 `CONFLICT + IMPORT_YEAR_AMBIGUOUS`，仅命中软删除记录或同名集合包含软删除歧义时按软删除冲突处理并要求用户补充年度。空年度仅表示省略定位信息，选择覆盖时必须保留数据库中的原年度，不能用空单元格清空它。
- **文件内重复与选择标识**：同一文件中，带年度行按业务键判重；空年度行完成上述唯一匹配后按目标项目 ID 判重。带年度行和空年度行只要最终指向同一项目，也视为重复冲突，不能对同一项目在一次导入中执行两次覆盖。匹配现有未删除项目时逐项目提示“`{项目名称}`项目已存在，是否覆盖”，用户必须选择“覆盖”或“跳过”；预览提供“全部覆盖/全部跳过”快捷操作，前端按 Excel 行号维护每个项目的最终选择并在确认请求中提交。选择映射由服务端按确认时重新解析的同一文件的行号校验目标项目，客户端不能直接决定写入对象。
- **批量导入规则与容量**：仅接受包含一个工作表的单个 `.xlsx` 文件；“单个文件/单个请求”不等于只能导入一个项目，一份文件可以批量包含最多 **10,000 个项目数据行**并在一次确认中统一新增或覆盖，项目行可以属于不同年度。上传文件最大为 **20 MiB（20 × 1024 × 1024 字节，界面可显示为 20 MB）**，两个限制均为 MVP 固定值，不放入系统设置，也不能由请求提高。标题行、表头、业务分类分组行和小计行不计入项目数据行数，但除可忽略内容的标题行外仍必须符合模板结构，不能用伪造非数据行绕过限制；接收字节超过上限立即以 `413 VALIDATION + IMPORT_FILE_TOO_LARGE` 终止，解析出第 10,001 个项目数据行时立即以 `VALIDATION + IMPORT_ROW_LIMIT_EXCEEDED` 终止，不继续读取或返回截断预览。浏览器上传后，服务端在当前请求内读取、校验并生成“新增 / 待选择 / 跳过 / 冲突 / 错误”预览，用户确认前不写入正式表。导入原文件不上传 OSS，不写入 PostgreSQL、Redis 或服务器磁盘，请求结束后不在服务端保留文件内容。分组行和小计行不作为项目导入；业务分类取所在分组上下文，系统虚拟分组“未分类”映射为数据库空值，其它分组必须匹配现有真实业务分类，并遵循下述停用项原引用往返规则。“备注”按普通项目级文本导入。自动计算列、小计、毛利率和单元格颜色只作核对/展示，服务端始终根据可导入字段值与金额明细重新计算语义和结果，不信任上传缓存结果或颜色；多笔金额按单元格换行拆分，任何手工金额为负数时整行校验失败并在预览中指出字段。
- **停用字典项的原引用往返**：地区、项目进度、业务分类和资料齐全度等字典项即使后来停用，导出仍按项目当前引用写出。导入新增项目只能选择当前启用项；覆盖已有项目时，上传的每个停用项只有在该目标项目当前已经引用同一字典记录、且本次覆盖继续保留该引用时才允许通过。资料齐全度为多选时，上传集合可保留该项目当前已有的停用项并增删启用项，但不能新增任何该项目原本未引用的停用项；单选字段不能从一个值改为另一个停用值。业务分类分组下若含停用分类，仅允许其中成功匹配且当前仍属于该分类的已有项目选择覆盖/跳过，不能在该组新增项目或把其它项目转入。这样既保证平台导出文件可覆盖回原项目，又不让停用项重新进入新业务选择。
- **XLSX 压缩容器安全**：除上传文件 20 MiB 上限外，ZIP 中所有条目的实际累计解压内容最多 **200 MiB**，条目总数最多 **1,000 个**；两个值均为 MVP 固定安全上限。解析前检查中央目录，实际读取时再次累计解压字节和条目数，不能只信任 ZIP 声明值；任一上限超出立即返回 `VALIDATION + IMPORT_ARCHIVE_LIMIT_EXCEEDED` 并终止解析。只允许 V2 模板需要的标准 XLSX 部件，拒绝加密 ZIP、嵌套压缩包、绝对路径、`..` 路径穿越、符号链接及其它非法条目；不得把压缩包解压到服务器文件系统。文件名、扩展名、客户端 MIME 和 ZIP 声明均不能代替文件特征与 Open XML 结构校验。
- **公式白名单**：上传文件中的公式只允许出现在系统定义的自动计算列“累计开票、累计收款、剩余未开票、剩余未收款、累计分包付款、暂定保通权益、毛利率”和业务分类小计行；导入端不执行这些公式，也不读取或信任其缓存结果，而是忽略后按数据库明细重新计算。任一可导入手工字段出现公式时，该项目行返回 `VALIDATION + IMPORT_FORMULA_NOT_ALLOWED` 并标明行号和字段，不把公式文本或缓存值当作业务值；因此系统导出的文件可以重新导入，但用户不能借公式影响手工数据。宏、外部链接、嵌入对象以及白名单外位置的公式仍按非法内容拒绝。
- **已有项目完整覆盖**：用户选择“覆盖”即以该项目的 Excel 行作为导入快照，完整覆盖模板中全部可导入的非自动字段；空白单元格也表示清空原值，不支持“仅用非空字段更新”。项目名称和已提供的年度用于定位记录并保持上传值；作为历史兼容而留空的年度是唯一例外，匹配成功后沿用现有项目年度，不视为清空。自动计算字段忽略上传值并在覆盖后重新计算。开票金额、已收回款和已付分包款按上传顺序整体替换原金额明细；服务端在同一导入事务中物理删除原金额明细，再按文件内容与顺序新建明细。由于 Excel 只保存多笔金额、不保存每笔日期和备注，覆盖会同时永久删除原明细的日期和单笔备注，并以日期和单笔备注为空的新明细重建；确认前必须对存在这类元数据的项目显示明确且不可跳过阅读的数据丢失警告。项目操作记录保存被替换明细的完整删除前快照与导入后快照；任何审计或重建失败时整次导入回滚。选择“跳过”则该项目完全不写入；新增项目必须提供年度，其金额明细日期与单笔备注为空。
- **精简预览响应与呈现**：预览响应固定返回新增、待选择、冲突、错误等状态的汇总数量；错误与冲突列表返回 Excel 行号、项目名称、年度、业务分类、状态和字段级安全错误；待选择列表额外返回目标项目的 `dataRevision` 与覆盖可能丢失金额明细日期/备注的警告标记，均不回传整行 28 列副本。合法新增项目仅返回汇总，同时返回仅含项目名称、年度和业务分类的精简清单。精简清单在本次预览响应中一次返回并由前端分页，不为此把解析后的 28 列业务内容保存到服务端，也不新增预览分页接口；用户需要核对完整原值时查看自己上传的 Excel。预览请求无服务端状态：服务端不保存原文件、单元格内容或预览元数据，待选择项目的覆盖选择由前端在当前页面内存中维护，确认时随文件一并提交。
- **预览确认、版本保护与无文件留存**：确认请求由前端使用仍保留在当前页面内存中的同一文件再次提交，携带预览返回的选择映射（Excel 行号 → 覆盖/跳过）与目标项目 `dataRevision`；服务端重新读取并完整校验文件，以重新解析的行号解释选择映射，并校验行号引用真实存在。对选择覆盖的每个项目，确认事务必须以提交的 `dataRevision` 为前置条件执行条件更新；对预览时不存在而选择新增的业务键，确认时仍必须不存在。任一待覆盖项目在预览后发生变化，或任一待新增业务键已被创建/恢复时，整批返回 `409 CONFLICT + IMPORT_PREVIEW_STALE`，不写入任何项目并要求重新预览；选择跳过的项目发生变化不阻断导入。文件在预览与确认之间被替换导致行号错位时，由 `dataRevision` 前置条件兜底：错位目标的版本校验失败，整批回滚。成功确认后无服务端状态需要清理；服务端不保存原文件或单元格内容，文件内容不写入浏览器持久化存储。- **单用户导入并发**：同一平台用户在全部浏览器、会话和服务实例之间，同时最多执行 1 个利润分析导入请求；该限制分别应用于预览请求和确认请求，只限制“正在执行的请求数”，不限制一个请求批量包含的项目数。导入与导出使用不同 Redis 并发键，因此同一用户可以同时执行 1 个批量导入和 1 个导出；平台不设置全体用户合计导入数的业务拒绝阈值。并发占用应在认证授权完成后、读取上传请求体前取得，并在响应结束、失败、取消或超时后安全释放；第二个导入请求不排队，返回 `429 RATE_LIMIT + IMPORT_ALREADY_RUNNING`。底层上传流、数据库连接池和主 PRD §9.1 CPU 工作池仍必须有界。
- **固定导入超时**：预览请求和确认请求的总时限均固定为 **120 秒**，本期不放入系统设置；从取得单用户导入占用并开始接收请求体时计算，覆盖上传读取、ZIP/Open XML 安全检查、等待和执行 CPU 工作、数据库匹配，以及确认阶段的全量校验、事务写入、项目操作记录和响应。到期返回 `503 TIMEOUT + IMPORT_TIMEOUT`，取消尚未开始的工作并向上传流、解析工作线程和数据库查询传播取消；确认事务尚未提交时必须完整回滚，不能在超时响应后继续后台写入或留下部分项目。确认超时且事务已回滚时允许用户使用相同文件和幂等键重试。Nginx 与 Node.js 超时必须高于应用层 120 秒，以便应用先完成受控取消和统一错误响应。
- **集合式导入执行**：预览匹配和确认校验必须把规范化键或目标项目 ID 集合化查询，确认写入采用参数化的集合更新、批量新增、批量重建金额明细和批量插入逐项目审计记录；禁止为最多 10,000 个项目逐行执行“查询一次、写入一次、审计一次”的 ORM N+1 往返。实现可以把集合拆成有界批次以控制 SQL 参数量和内存，但全部批次必须处于同一个数据库事务，不能以批次为单位提前提交。带 `dataRevision` 的条件更新完成后必须核对受影响项目集合和数量，任何缺失都按预览过期整批回滚；不得为追求速度绕过字段校验、操作记录或金额明细替换审计。
- **导入原子性与安全**：V2 不额外增加“模板版本”业务列，服务端通过空白运行模板定义的“仅一个工作表”、28 列有序表头和关键合并/分组结构的版本化签名识别模板；第 1 行标题文字及工作表名称不参与签名或校验，同时校验列顺序、文件大小、最大行数、单元格类型与长度，并按上述白名单处理公式、宏、外部链接和嵌入对象。只有已选择的新增和覆盖项目参与写入，跳过项目排除在事务外；参与写入的项目在确认请求内全量成功或全量失败，冲突、待选择或任一错误不得产生部分写入。确认接口支持幂等并记录每个项目的新增/覆盖/跳过结果及覆盖警告确认；导入不创建异步任务、服务端临时文件或可恢复的导入草稿，失败后由用户修正文件并重新预览。
- 只读用户（财务数据查看）看到纯展示内容，不出现编辑或删除入口；编辑失败保留已输入内容。

## 5. 项目操作记录

- 权限：随 fin 功能“财务数据查看”开放（“财务数据维护”隐含包含），在财务系统内提供只读列表与详情页，不单独拆分授权项。
- 自动记录项目新建、合同信息修改、财务数据修改、明细增删改和项目删除；提交前后无实际差异时不产生记录。单条物理删除金额明细时必须记录被删明细的完整删除前快照，Excel 覆盖重建金额明细时必须记录该项目替换前后的完整明细快照，且审计记录与业务变更处于同一个数据库事务。
- 列表按时间倒序展示操作时间、操作人、动作、项目和变更摘要；详情按字段展示变更前后内容。
- 记录只追加，不能修改或删除；项目删除后操作记录仍保留。

## 6. 财务配置（系统内页面）

- 权限：fin 功能"财务配置"。
- 「菜单管理」页签：调整本系统侧边导航的顺序、分组层级与显示名，规则见主 PRD §2.1。
- 业务字典：项目进度、资料齐全度、业务分类、**地区**（跨系统地区选项统一在财务系统维护）。每个项目进度选项必须带结构化金额语义 `TENTATIVE（暂定）/AUDITED（审定）`；创建时必选，已被项目引用后不得修改该语义，只能停用旧选项并新建选项，避免历史项目的“暂定/审定金额”含义和颜色被全局改写。业务分类允许项目为空，但真实字典项名称不得与 §4 的系统虚拟分组“未分类”冲突。
- 选项可新增、编辑、排序、启用和停用，并按主 PRD §2.6 批量硬删除未被引用的字典项；正在被历史项目引用的选项不能删除，任一目标已被引用时整批拒绝。停用后历史项目仍显示原有内容。
