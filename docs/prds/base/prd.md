# 基础模块 PRD（base）

> 本文档定义 WBME 企业管理平台**基础模块**的需求。
> base 与 backstage 共同运行于部署单元 `platform-core` 中（见主 PRD §1.3），本文只描述 base 逻辑模块。
> 平台级通用机制（功能权限、统一审批、软删除、基础设施、前端规范等）见主 PRD：`docs/prds/prd.md`。

---

## 1. 模块定位

- base 为全员可用的基础模块，承载注册与登录、会话管理、登录保护、统一门户、个人中心。
- base 功能不进入功能权限授权目录（授权目录见主 PRD §2.5）；base 相关实体与 backstage 共同归属 `platform-core` 部署单元，通过明确的模块边界协作（见主 PRD §9.4）。

## 2. 钉钉注册与双通道登录

- 登录页同时提供**钉钉扫码登录**与**手机号 + 密码登录**；两种方式登录同一个平台账号，不得因登录方式不同创建重复账号。
- 钉钉接入使用本公司配置的企业内部应用和唯一组织标识；每次扫码注册、邀请激活和扫码登录都必须由后端校验授权结果所选组织与部署配置的公司组织一致，并通过钉钉企业身份接口确认该身份是本组织成员。其它组织成员、外部联系人或普通个人钉钉账号不得注册、激活或登录本平台；组织确实不匹配时统一提示“当前钉钉账号不属于本公司组织”，不泄露平台内账号信息。钉钉接口超时或不可用时按主 PRD §9.5 返回依赖不可用，不得误报为非本公司成员，也不得跳过校验继续登录。该校验只用于身份准入，本期仍不从钉钉自动同步部门、岗位或功能权限。
- 手机号 + 密码登录只校验平台内账号状态、密码和登录保护，不在每次密码登录时调用钉钉接口；这样钉钉暂时不可用时，已激活且未注销员工仍可使用独立密码通道。离职或其它禁止访问的权威状态以 backstage PRD §3 平台账号注销为准，账号管理流程必须及时注销离职员工，不能依赖钉钉成员状态自动替代平台生命周期；反过来，钉钉通讯录变化也不得自动恢复或修改平台账号。扫码登录、注册/激活、钉钉验证式密码重置仍实时执行上条成员校验，不能复用过期成员结果绕过准入。
- 首次钉钉扫码时，后端使用钉钉当前官方授权流程换取用户身份，以钉钉返回的**稳定唯一用户标识**作为绑定依据，不使用姓名、手机号或显示名作为外部身份主键。
- 扫码身份已绑定平台账号时直接登录；未绑定且未携带账号邀请时，由后端签发限时、一次性注册会话并进入注册完善页。手机号必须取自本次钉钉授权结果并只读展示，用户填写或确认姓名、性别并设置平台密码，最终确认后才创建账号和绑定关系；超时或已使用的注册会话不得重放。
- 管理员预先创建的基础账号处于“待激活”状态，不设置初始密码，也不能直接登录。创建成功后生成指向同一激活凭证的**一次性二维码与链接**，由管理员交给对应员工；凭证使用密码学安全随机值，数据库只保存摘要，默认 7 天有效且有效期可在系统设置中调整。重新生成邀请会立即使旧邀请失效，二维码与链接任一方式使用成功后另一方式同步失效，邀请原文不得进入访问日志、操作日志或前端持久存储。
- 激活、密码重置的一次性链接统一把凭证放在前端固定入口的 URL fragment 中（如 `/activate#<token>`），不得放在 path 或 query。页面读取后立即以 HTTPS 请求体提交给受限兑换接口，由后端校验并换成 Path 仅覆盖对应流程的短时 `HttpOnly + Secure + SameSite` Cookie，同时从地址栏移除 fragment；原始凭证只允许在兑换前短暂存在于当前页面内存，不写入 `localStorage`、`sessionStorage`、Cookie、前端分析或错误日志。后续钉钉跳转与回调只携带服务端生成并校验的一次性 `state/nonce` 和流程标识，不再携带原始凭证。兑换、回调和最终确认均限流，任何服务端日志不得记录请求体中的完整凭证。
- 员工打开邀请链接或扫描邀请二维码后必须完成钉钉授权；钉钉稳定标识必须尚未绑定任何账号，且钉钉返回的手机号未被其他“待激活/正常”账号占用。激活的身份要素是钉钉稳定标识加一次性邀请，不再要求与创建时预留的手机号一致；预留手机号仅作激活前的联系参考。校验通过后签发短时一次性激活会话，员工确认姓名、性别并设置密码；完成时在同一事务中绑定钉钉身份、把账号手机号设置为钉钉本次返回的号码、写入密码并将账号改为正常状态。邀请无效、过期、已使用、手机号被占用或账号已激活时均拒绝激活；管理员可在用户管理中为仍处于待激活状态的账号重新生成邀请。
- 一个钉钉账号只能绑定一个平台账号，一个平台账号也只能绑定一个钉钉账号；重复绑定必须拒绝并提示走账号恢复流程。
- 已注销账号继续占用原钉钉稳定标识：注销期间及之后均不得使用同一钉钉账号注册或绑定第二个平台账号；扫码或手机号登录命中已注销账号时提示”账号已注销，请联系管理员恢复”，不得泄露其它账号信息。手机号不随注销永久占用：注销后原手机号转为历史快照保留，不再参与唯一性校验（见下条），可被其他员工后续的注册、激活或同步使用；账号恢复时按 backstage PRD §3 做手机号唯一性兼容检查。
- 手机号以钉钉本次授权返回的号码为准，平台不提供任何手工修改入口（员工与管理员均不可编辑），本期不接入短信验证；钉钉未返回手机号时不能注册或激活，提示联系管理员检查钉钉通讯录资料。手机号唯一性只在“待激活 + 正常”账号之间强制（已注销账号的手机号仅为历史快照）。
- **手机号自动同步**：平台手机号始终跟随当前绑定的钉钉身份，不关注“员工是否想改手机号”，只关注“钉钉侧是否已变更”。每次钉钉授权（扫码登录、注册、激活、钉钉验证式密码重置）返回的手机号经规范化后与账号现有手机号比对，不一致时在当次流程的事务中原子更新为新号码并写入安全日志（记录脱敏的前后端值）；同步前按上条范围做唯一性校验，新号码已被其他“待激活/正常”账号占用时跳过本次同步并写入安全日志冲突事件（扫码登录本身不受影响），冲突随占用方下次授权同步或注销后自然解除。
- 手机号在写入、唯一性校验和登录查询前统一规范化为“国家/地区码 + 号码”的平台标准格式，显示时再按前端规则格式化，避免 `+86`、空格或连字符等表现差异造成重复账号或同步误判。
- 注册用户默认为普通员工，不自动获得部门、岗位或业务系统权限。
- 平台账号状态固定为“待激活 / 正常 / 已注销”三种；主 PRD 各章节所称“在职”员工，均指账号处于“正常”状态（已激活且未注销）的员工。
- 钉钉授权回调必须校验有效期、回调地址和一次性 `state/nonce`，授权码只能使用一次；钉钉应用密钥、用户访问凭证只在后端保存和使用，不下发前端、不写入普通日志。
- 管理员预先创建的待激活账号不得仅因普通扫码返回相同手机号就自动绑定，必须携带该账号仍然有效的一次性邀请并完成上述激活流程。
- 未携带邀请的扫码注册若发现该手机号已被待激活基础账号占用，不创建第二个账号，也不自动绑定；页面提示“已有待激活账号，请联系管理员获取激活邀请”。若该手机号被正常状态账号占用，提示“该手机号已被使用，请联系管理员处理”，占用随该账号下次授权同步或注销后自然解除。上述提示仅在钉钉授权已返回同一手机号后展示。
- 手机号 + 密码登录失败不泄露账号是否存在（统一错误提示）；例外为两种明确提示的状态：已注销账号提示"账号已注销，请联系管理员恢复"（见上），待激活账号提示"账号尚未激活"。上述两种状态的前置拒绝同样计入 IP 锁失败计数，不记账号锁（待激活账号无密码，"账号锁"只针对密码校验失败；计账号锁会让撞库探测可恶意锁死真实员工）；连续尝试过多时暂时限制登录（见 §4）。
- 支持登录、退出、查看当前身份、修改密码；已绑定钉钉的用户可重新扫码完成钉钉验证（稳定标识与组织成员校验，与 backstage PRD §3 管理员发起的重置同一标准）后重置密码，重置完成时按手机号同步规则更新手机号。修改或重置密码成功后原有登录状态全部失效，需重新登录。
- 平台密码只校验长度为 8～32 个字符，要求二次输入一致；本期不要求大小写、数字、符号组合，不做常见密码拦截、强度评分或周期性强制修改。

## 3. 会话管理

- 会话支持空闲超时（滑动过期）与绝对过期双重限制，两种机制独立生效。
- 默认值：未勾选"记住我"时，空闲超时 1 天（产生有效用户操作时续期）、绝对过期 1 周；勾选"记住我"时，默认延长为空闲超时 30 天、绝对过期 90 天。两组数值均可在系统设置中调整。空闲续期只由已认证用户在前台触发的页面导航、查询、提交或编辑等有效交互产生；定时轮询、健康检查、预取、静默刷新、失败重试和浏览器后台标签页的自动请求不得续期，不能让无人操作的常开页面无限保持活跃。
- "记住我"只表示延长空闲与绝对过期时限，不得取消绝对过期或创建永不过期会话；登出、修改/重置密码、账号注销等强制失效规则不受该选项影响。勾选"记住我"时，会话 Cookie 随服务端绝对过期时限持久化（浏览器关闭重开仍保持登录，Cookie `maxAge` 与服务端时限一致）；未勾选时为浏览器会话级 Cookie，关闭浏览器即需重新登录。
- **高危操作不做二次身份认证**：MVP 不建设通用“高危操作会话”或权限提升状态。已登录用户执行超级管理员任免、授予/撤销"权限管理"功能、整库恢复确认等高危管理操作时，不要求重新输入密码或再次钉钉扫码；只要当前普通会话仍有效即可进入操作流程。该决定不免除危险操作二次确认、当前角色/权限和授权版本复核、CSRF、幂等、状态条件更新及操作/安全审计；会话已过期、账号已注销或权限刚被撤销时仍须按正常规则重新登录或拒绝操作。不得为该需求在 Redis 或数据库新增 `stepUp/elevated` 状态。
- 登录成功、权限或站点角色提升后必须更换会话标识，防止会话固定。会话只保存用户标识和必要会话状态，不把登录时的功能权限、数据范围、部门或站点角色当作整个会话期内不变的授权事实；每个受保护请求由守卫按当前账号状态和授权版本取得最新授权上下文。`platform-core` 的授权编排服务在 backstage 员工授权/站点角色事务中同步递增 base 账号授权版本，并在代码注册的功能目录发生新增、移除、归属或可选范围变化时递增全局权限目录版本；这两个逻辑模块通过主 PRD §9.4 的公开进程内接口参与同一个数据库事务，不由 backstage 私有代码直接写 base 表。hr 在用户组织关系事务中递增用户组织版本，并在部门父子关系、停用或删除等会改变部门范围闭包的事务中递增全局组织树版本。守卫通过当前账号/权限记录和 hr 只读组织视图取得“账号授权版本 + 权限目录版本 + 用户组织版本 + 组织树版本”，只有四项均与缓存快照一致时才可复用 Redis 授权上下文。Redis 失效广播只用于加速刷新，不作为撤权正确性的唯一保障。旧会话下一次请求必须重新加载当前权限；撤权、功能移除或范围定义变更、降级、调岗、部门树调整和注销立即影响后续请求，不等待会话或缓存过期，提权时除刷新授权外还必须旋转会话标识。
- 修改密码或管理员重置密码后，该用户全部会话失效；账号注销后会话即时失效。
- 会话中途失效时用户得到明确提示并重新登录，不产生无提示跳转。

## 4. 登录保护

- 手机号 + 密码通道提供两级锁定：**账号锁**（同账号连续失败默认 10 次，锁定 10 分钟）与 **IP 锁**（同来源 IP 在计数窗口内累计失败达到上限即锁定；默认窗口 60 分钟、上限 120 次、锁定 1 小时，默认值按公司全员共享办公网出口 IP 的口径设定）。账号锁的次数与时长，以及 IP 锁的计数窗口、次数上限与锁定时长，均可在系统设置中调整，不是固定值。锁定与管理员解锁事件按 backstage PRD §8 写入安全日志。钉钉授权发起与回调接口另行按 IP、会话和一次性状态值限流。
- 锁定时登录页明确提示"尝试过多，请稍后再试"。
- 管理后台「用户管理」提供"解锁账号"操作（权限归"用户管理"功能，见 backstage PRD §3），解锁后该账号立即恢复可登录。

## 5. 统一门户

- 登录后的落地页为门户，展示：WBME 品牌、按权限推导的系统入口、始终可见的**个人中心入口**，以及**系统公告入口**（不常驻展示内容）。
- 门户提供系统公告查看入口：查看当前唯一“正在展示”的系统公告（只读）；不存在正在展示的公告时显示“暂无公告”。门户不展示历史已撤回公告或更新日志。
- 系统入口可见规则：当前用户拥有该系统至少一项功能授权；入口可见不等于可进入，"即将上线"或运行不可用的系统展示说明与状态但不可进入。超级管理员视为拥有所有系统功能，可见全部系统入口。
- 系统入口展示当前用户的待处理数量角标（按对应审批功能的数据范围统计，口径与各系统审批中心一致）；无待办时不显示角标。
- 进入业务系统后落入该系统首页。

## 6. 个人中心

- 查看当前身份信息。
- 修改姓名和性别：超级管理员修改立即生效；普通员工修改提交**资料修改审批**（由管理后台"用户管理"功能持有者审批，见 backstage PRD §3），审批通过后生效；性别固定只有"男/女"两个选项。手机号只读展示（以 §2 的钉钉授权自动同步为准），任何角色均不能在平台内手工修改。
- 修改密码：成功后全部会话失效，需重新登录。
- 提交**岗位变更申请**：每张申请只能选择一个目标部门和一个目标岗位，不支持在一次申请中选择多个部门或多个岗位。该自助流程仅面向当前无部门或仅属于一个部门的员工；已属于多个部门的员工不能通过个人中心变更组织关系，应联系持有“组织架构”功能的管理员手工调整。选择目标部门后，岗位下拉只展示当前已启用、允许员工自助申请且适用于该目标部门的岗位；提交和审批通过前均由后端重新校验这三项条件。审批通过后将员工的所属部门更新为唯一的目标部门、岗位更新为唯一的目标岗位，并再次校验员工仍未变为多部门员工。
- 个人中心内可查看本人的岗位申请记录。
- **我的操作日志**：全员可用，无需授权；仅查看本人的全部操作日志，按系统、功能、操作性质、时间等条件筛选（机制详见主 PRD §3.3）。
- 能否同时存在多条待处理申请由具体业务规则决定，不设平台级统一限制：资料修改与岗位变更分别遵循主 PRD §3.2 的单待审批限制，消耗品、加班等申请遵循各自业务章节。审批通过前不改变正式资料；审批记录作为审计信息保留，不提供删除或覆盖。

## 7. 实现约定（开发期敲定，随实现同步维护）

### 7.1 系统设置键名清单（T2 起读取侧生效；管理界面 T4-5）

| 键名 | 默认值 | 说明 |
| --- | --- | --- |
| `session.idle.timeout.seconds` | 86400 | 普通会话空闲超时（秒） |
| `session.idle.remember.seconds` | 2592000 | "记住我"会话空闲超时（秒） |
| `session.abs.timeout.seconds` | 604800 | 普通会话绝对过期（秒） |
| `session.abs.remember.seconds` | 7776000 | "记住我"会话绝对过期（秒） |
| `login.account.max.attempts` | 10 | 账号锁连续失败次数上限 |
| `login.account.lock.seconds` | 600 | 账号锁定时长（秒） |
| `login.ip.window.seconds` | 3600 | IP 锁计数窗口（秒） |
| `login.ip.max.attempts` | 120 | IP 锁窗口内失败次数上限 |
| `login.ip.lock.seconds` | 3600 | IP 锁定时长（秒） |
| `invitation.valid.seconds` | 604800 | 激活/重置凭证有效期（秒） |

### 7.2 手机号规范与脱敏

- 平台标准存储格式：`+{国家码}{号码}`（如 `+8613800138000`），只含数字与前置 `+`；写入、唯一性校验与登录查询前统一规范化（钉钉 `stateCode` + `mobile` 或用户输入均可解析）。
- 脱敏展示：保留国家码与前 3 后 4，中间以 `****` 掩蔽（如 `+86 138****8000`）；完整手机号不出现于安全日志上下文、操作日志、错误详情或导出。

### 7.3 会话与 CSRF 实现方案

- 会话 Cookie：`wbme_session`，`HttpOnly + Secure（部署配置）+ SameSite=Lax + Path=/`；SameSite=Lax 允许钉钉 top-level 授权回跳携带 Cookie，同时挡住跨站 POST。`maxAge`：勾选"记住我"时为服务端绝对过期时长（跨浏览器重启持久），否则不设置（浏览器会话级，见 §3）。
- 空闲续期只由"有效交互"产生：前端请求层写请求默认携带 `X-WBME-Active: 1`，读请求仅页面导航/用户查询携带；轮询、预取、静默刷新、失败重试与后台标签页不携带。
- CSRF：双提交 Cookie `wbme_csrf`（非 HttpOnly）+ 自定义头 `X-WBME-CSRF-Token`；状态变更且携带会话 Cookie 的请求校验；钉钉回调（GET）由一次性 state 承担。
- 一次性流程 Cookie：`wbme_flow`，`Path` 覆盖 `/api/v1/auth` 前缀（钉钉授权发起/回调与激活/注册/重置全部流程路由），值对应 Redis 一次性流程会话（TTL 30 分钟，确认成功后或失败即删）；流程标识随一次性 `state/nonce` 交给钉钉回调，回调侧从 state 取流程会话，不依赖流程 Cookie 送达钉钉路径。
