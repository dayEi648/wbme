## 2. 面向用户

普通员工（查看本人负责/使用的固定资产、查看可申领物品、提交申领、查看本人记录、发起归还/核销）、固定资产只读人员（查看范围内台账）、资产管理员（维护固定资产、消耗品、库存、分类、库位、字典）、审批人（处理入库、库存异常、申领、归还、核销待办，并直接处置已注销员工的个人借还）。功能授权与权限组由持有平台"权限管理"功能的人员统一管理（见 backstage PRD §4）。

## 3. 分类体系

- 系统提供"固定资产、消耗品"两个顶级分类；业务人员只维护其下的一级子分类（不能继续建立下级分类）。"车辆"顶级分类本期不提供，后续与钉钉"车辆在线"服务对接时引入。
- 子分类名称在同一顶级分类下不能重复；固定资产只能归入固定资产分类，消耗品只能归入消耗品分类。
- 分类按主 PRD §2.6 提供批量硬删除：资产与品种只保存分类名称快照，删除前展示仍引用该分类的资产/品种数量并要求确认，确认后物理删除，历史引用不受影响；仍可随时停用。

## 4. 固定资产查看与维护

- **台账**：每项资产一条台账（名称、分类、规格型号、金额、入库时间、使用状态、资产归属、所属部门、责任人、使用者、备注、可选主图）；**一条台账对应一件资产**。
- **状态**：闲置、使用中、待维修、维修中、已报废。
- **归属**：公司自有、合作方所有（记录归属方名称）。
- **我的资产**（权限“我的资产”）：只展示责任人或使用者为当前用户的资产；提供“我负责的 / 我使用的 / 全部”筛选，同一资产同时命中两类时合并为一条；可查看详情、主图、二维码和历史，不提供维护与导出入口。
- **固定资产查看**（权限“固定资产查看”，部门/公司）：分页查看范围内台账，可按分类、部门、状态、归属、责任人、使用者搜索筛选；可查看完整资料、主图、二维码、调度历史、变更历史和维修历史，并支持导出所有未逻辑删除数据或导出全部筛选结果，不提供当前页导出；不出现任何维护入口。
- **固定资产维护**（权限“固定资产维护”，部门/公司）：隐含同范围“固定资产查看”；可新建建档（金额必填，单位元保留两位小数；可上传主图）、编辑基础资料/使用者/主图、批量软删除无业务关联资产、调度、登记变更、管理二维码和报废。普通编辑只允许在资产未处于“待维修/维修中”时切换“闲置/使用中”；“待维修、维修中”只能由维修管理产生和流转，不能通过普通编辑写入或跳出。“已报废”由报废动作产生，但拥有当前数据范围“固定资产维护”的人员可以通过编辑资产把已报废状态恢复为“闲置”或“使用中”，不另建报废纠正流程。仍在使用或有业务关联的资产不允许删除。
- **维修管理**（归属“固定资产维护”）：专用于固定资产维修状态管理。只有当前为“闲置/使用中”的资产可以登记维修；登记时选择资产，填写故障/维修事项和报修时间（默认当前时间），在维修单中保存资产进入维修前的状态快照，并把资产当前状态改为“待维修”，此时不强制填写尚未发生的费用或耗时。尚未开始的“待维修”维修单允许执行“取消登记”，取消后维修单进入只读“已取消”终态并把资产恢复为登记前状态，不删除该单；“维修中”不能取消，只能完成。执行“开始维修”时记录开始时间并把资产从“待维修”转为“维修中”；执行“维修完成”时填写维修结果、实际费用（无费用时为 0）和完成时间，耗时由开始时间与完成时间自动计算，再选择把资产恢复为“使用中”或“闲置”。同一资产同一时刻最多只能存在一张“待维修/维修中”的维修单，由事务内状态校验和 PostgreSQL 条件唯一索引共同保证；登记、取消、开始和完成均在事务内使用当前状态与版本号条件更新，并发重复操作只有一个成功。维修单及状态流转历史只追加，不因资产之后报废、恢复或删除而改写。
- **规则**：资产的所属部门允许为空（部门被删除时按主 PRD §2.6 规则置空）；责任人和所属部门的变化必须产生调度记录，不能被普通编辑绕过；调度目标责任人必须属于目标部门；部门和责任人均未变化不允许提交。部门范围“固定资产维护”只能新建、编辑和调度当前所属部门与目标所属部门均位于其授权部门闭包内的资产，跨出授权闭包的调度必须由公司范围维护者执行；不能以先取得来源资产详情的方式把资产或责任关系写入无权管理的部门。调度记录、变更记录与维修单只能追加；变更记录只描述历史事件，不直接改变资产状态；“待维修/维修中”状态由维修管理驱动。报废需二次确认，但“已报废”只是固定资产的一种业务状态，不表示删除、软删除或从台账隐藏：已报废资产继续出现在固定资产台账、搜索结果、详情、历史和符合条件的导出中，并可按状态筛选；责任人或使用者关系仍然保留时，也继续显示在对应员工的“我的资产”中。通过编辑恢复状态时按普通资产编辑保存并记录状态变更前后值和操作人，不删除或覆盖此前的报废操作记录。

## 5. 消耗品管理

**业务概念**

| 概念 | 说明 |
| --- | --- |
| 品种 | 物品是什么：名称、分类、单位、安全库存、参考单价、图片、备注。 |
| 批次 | 某次入库的供应商、品牌、规格、库位、数量、单价和时间；用于采购与库存追溯。批次的入库时间取入库申请整单的申请时间（默认提交时，可手工填写）。 |
| 库存条目 | 同一品种中“规格 + 库位”相同的批次合并展示，是申领和库存扣减的直接对象；品牌、供应商和价格不同不拆分库存条目。 |
| 库存流水 | 库存为什么增加或减少，以及操作前后的数量。 |

**品种类型**（创建时确定，创建后不可改变）：

- 一次性用品：发放后视为消耗；创建品种时必须选择申领上限的周期类型（月 / 季 / 年）并填写该周期内的数量上限，二者均为品种级配置（每个新增消耗品必填）。
- 申领上限的重置时点由资产配置中的全局参数"申领上限重置日"统一决定（默认每月 1 号，见 §12）：月度上限在每个自然月的重置日重置，季度上限在每季度首月的重置日重置，年度上限在每年 1 月的重置日重置；周期边界按主 PRD §9.10 的北京时间计算，重置日变更只影响之后开始的周期，不追溯改写进行中的周期。
- 借还用品：发放后需归还，可配置归还期限（单位：天）和同时持有上限，不使用周期申领上限。

**功能**：品种档案的新建、查看、编辑、停用和批量硬删除；品类参数（申领上限、归还期限、同时持有上限）随品种编辑一并维护，参数变化留下前后值和操作说明；库位维护（全公司统一的层级库位树，入库时选择，历史可追溯）；库存管理（品种、库存条目、批次、账面库存、占用库存、可用库存、低库存标记）；轻量库存调拨；库存流水查看（按品种、类型、来源、时间查询并导出，只追加）。

- **品种删除限制**：品种按主 PRD §2.6 配置类数据规则硬删除，历史记录存品种名称快照，删除后同名品种可再建并获得新 ID；但品种是库存条目的身份本身（不同于库位仅是位置标签），存在当前账面/占用库存、未结清借还或待审批引用时仍整批拒绝删除（可先停用并消化库存），仅有历史终态记录引用时可确认后删除。

- **库位生命周期**：库位树支持新建、编辑、排序、停用和批量硬删除（按主 PRD §2.6 配置类数据规则），并禁止形成父子循环；存在未删除子库位时禁止删除父库位。批次、库存条目与流水只保存库位名称/路径快照；删除前展示现存库存条目数、未结清借还数和待审批引用数并要求确认，确认后物理删除。库位停用后不能作为新入库或调拨的目标，但现存库存、历史批次和流水继续显示，且允许按 §6 把库存调出；之后发生的正常归还仍作为明确例外回到批次快照所示的原库位（即使该库位已停用或已删除）并正常显示库存，再由库存管理员调拨到启用库位，不能因库位停用或删除拒绝已经发生的归还。库位改名或移动节点只改变当前树和当前库存位置展示，已有库存流水与审批快照保留当时路径，不能追溯改写。
- 品种单位在尚未产生任何入库批次、申请明细、库存流水或借还记录时允许纠正；一旦已有业务事实即不可修改，避免把历史整数数量从“个”无痕改成“箱”等不同口径。安全库存修改即时影响低库存标记；申领上限、归还期限和同时持有上限只影响修改后新提交/新借出的业务，既有待审批占用和借还期限继续使用提交或出库时快照，不追溯重算、自动取消或强制结清。
- **已批准批次纠错**：入库批准后，原入库申请、批准数量、入库时间和既有库存流水不可编辑或覆盖。持有“消耗品库存管理”者可通过批次详情的“纠正批次资料”修改供应商、品牌、单价和批次备注，这些字段不参与库存条目分组，纠正必须记录前后值、原因和操作者，原入库申请仍展示提交/批准时快照。规格或库位会改变库存条目归属，仅当该批次除原始入库外从未发生出库、归还、核销或其它后续流水，且来源库存条目当前没有任何待审批占用时才允许纠正；服务端在一个事务中锁定批次和相关库存条目，重新归并账面数量并记录纠正流水/审计。任一条件不满足时，规格仍不得修改；实际库存只是移动到其它库位时改用下述库存调拨，不能覆盖原批次库位制造虚假历史。批准数量和现存数量不提供直接改数入口：本期多录造成的真实扣减仍走库存变更申请，少录则补提新的入库申请，不能以“纠错”绕过审批和库存流水。

**库存规则**

- 入库、调拨、申领、意外扣减、归还、遗失/损坏核销和代领结清等所有由用户或接口提交的物品变动数量必须是**正整数**；不接受小数、零、负数、科学计数法或非数值文本。数量字段和额度字段使用 PostgreSQL 整数类型及检查约束，库存增减方向由业务类型/流水方向表达，不使用负数数量表达扣减；计算后的账面库存、占用库存、可用库存、已归还量和已核销量可以为 0，但不得小于 0。单位只是展示与业务分类，不改变 MVP 的整数精度规则。
- 账面库存 = 已入库未出库/未损耗；占用库存 = 已被待审批申请预留；可用库存 = 账面 − 占用。
- 提交消耗品申领或库存意外扣减申请时先占用可用库存；批准后扣减账面，驳回或人工取消时释放占用。申请待审批期间占用一直保留，不设置有效期或自动释放；释放占用与申请转终态必须在同一数据库事务内完成。
- 品种汇总、库存条目汇总和批次汇总必须一致；出库按批次入库时间（即申请时间）先后扣减，申请时间相同的批次按批准入库先后排序，保留每批变动记录。
- 库存调拨只改变同一品种、同一规格库存的库位归属，不改变全公司账面总量、占用总量、个人额度或持有量；来源与目标库存条目的调拨流水数量绝对值必须相同，一减一增并关联同一调拨记录。
- 允许同一库存条目同时存在多张待审批申请，不因“已有未处理申请”阻止后续提交；每张申请提交时必须在数据库事务内原子校验并增加占用库存，只有增加占用后仍满足 `占用库存 ≤ 账面库存` 才能成功。数量不合法或可用库存不足时不能提交；审批通过时再次校验申请占用和账面库存状态，但不得重复占用。
- 消耗品申领和库存意外扣减申请均按**整张清单全有或全无**处理，同一库存条目在同一张清单中最多出现一次。提交时按库存条目标识的固定顺序锁定全部目标并在同一事务中完成全量校验和占用；任一行重复、数量非法、目标不可用或库存不足时，整张清单不创建且不增加任何占用。批准时同样按固定顺序锁定并在一个事务中把全部占用转换为账面扣减和库存流水；任一行校验失败时保持整张申请待审批，不得部分批准、部分出库或产生部分流水。
- 普通员工申领除库存占用外，还必须在提交事务中原子占用个人额度：一次性用品按“员工 + 品种 + 当前周期”校验 `已批准使用量 + 待审批占用量 + 本次数量 ≤ 申领上限`；借还用品按“员工 + 品种”校验 `当前未结清持有量 + 待审批占用量 + 本次数量 ≤ 同时持有上限`。额度配置和所属周期在提交时形成快照，额度占用随申请明细持久化在 PostgreSQL，不能只放 Redis。
- 一次性用品的额度周期以**提交时间**为准：例如自然月口径下 12 月提交的申请始终占用并最终计入 12 月额度，即使到次年 1 月才批准，也不得迁移到批准月份或重新竞争新周期额度。月/季/年边界均按主 PRD §9.10 的北京时间计算。
- 普通申领批准时把对应待审批额度占用转换为已使用量或实际持有量，不重复增加；驳回或人工取消时在同一事务释放。多个并发申请按员工、品种和周期的固定顺序锁定额度事实记录，任一物品额度不足时整张清单提交失败且库存占用与额度占用均不产生。代交申领继续按 §7 的明确例外，不占用任何个人额度。
- 低库存以品种可用库存与安全库存比较，缺货优先展示。品种停用表示停止新的采购入库和领用，不要求先把库存、待审批申请或未结清借还全部清零：停用后不再出现在新建入库、普通/代交申领选择器中，但既有库存仍在库存管理中可见，库存变更申请仍可选择并明确标记该停用品种，以便按审批流程处理真实盘亏或其它意外扣减；停用前已提交的申请仍可批准、驳回或取消，既有借还仍可归还或核销。停用不删除历史，也不能绕过库存流水；重新启用后才允许创建新的采购入库或领用申请。
- 申领人按“品种 + 规格 + 库位”判断和选择物品；申领目录不以品牌、供应商、采购价格区分可申领项，也不向申领人承诺具体批次。批准出库时系统再按批次入库先后自动分摊，并保留实际扣减批次用于追溯。

## 6. 入库、库存变更与库存调拨

- **入库申请**（消耗品模块，含"入库申请 / 历史记录"两个视图）：**清单式提交**：一张申请可含多行，每行选择品种并填写供应商、品牌、规格、库位、数量及可选单价，整单可填申请时间（默认提交时）与备注；整单进入审批（整单批准或驳回，驳回需说明原因）；批准后按行形成批次、增加库存并生成入库流水。
- **库存变更申请**：仅处理非正常领用造成的**意外库存扣减**，MVP 不支持通过该功能增加库存；正常新增库存必须走入库申请，正常领用必须走消耗品申领。清单式提交：一张申请可含多行，每行选择品种与库存条目、填写扣减数量、变更类型与具体原因，同一库存条目在整张申请中只能出现一次；类型来自可扩展字典，MVP 至少提供“其他意外扣减”，具体原因必填。整单可填变更时间（默认提交时）与备注；批准后按行按批次扣减库存并生成流水，驳回需说明原因。
- **历史记录**：本人历史随"入库申请"/"库存变更申请"权限隐含提供（仅本人）；范围历史由"入库申请历史记录"/"库存变更申请历史记录"权限（部门/公司）提供，支持按审批状态、发起时间区间、查看范围与发起人姓名筛选。

**轻量库存调拨**（权限归“消耗品库存管理”，公司范围）

- 库存管理对每个存在可用库存的库存条目提供“调拨”操作，并提供“调拨记录”查看。单次调拨只处理一个来源库存条目：目标库位必选，调拨数量为正整数，备注可选；不建设多行调拨单、调拨草稿、审批流程或 BullMQ 后台任务。
- 调拨是已授权库存管理员的直接业务操作，不进入 §9 审批中心。前端是否显示按钮不构成授权依据；创建与查看调拨记录接口都必须由服务端重新校验登录状态和“消耗品库存管理”权限。写接口使用名词资源 `POST /api/v1/asset/inventory-transfers`，列表接口使用同一复数资源并按主 PRD §9.5 分页；输入和输出 DTO、错误码及 OpenAPI 契约随实现提交，不另建带动词的私有接口。
- 来源库存条目必须仍存在且账面库存大于 0；目标库位必须存在、当前启用且不同于来源库位。来源库位已经停用时仍允许把现存库存调出，便于清空旧库位，但不能作为新的目标库位。调拨固定保留原品种与规格，不能借调拨修改规格、单位、供应商、品牌、单价或库存总量；品种已停用但仍有实际库存时允许移库，不代表重新允许采购或申领。
- 可调拨数量固定为来源库存条目的当前可用库存，即 `账面库存 − 待审批占用库存`；不得移动任何已被申领或意外扣减申请占用的数量。提交确认时服务端不能信任页面预览值，必须在一个 PostgreSQL 事务中按稳定 ID 顺序锁定来源库存条目、可能存在的目标库存条目和所需批次，重新计算可用库存；数量超过当前可用库存、来源/目标状态变化或并发导致条件不再成立时，整次返回 `CONFLICT`，不产生调拨记录或任何流水。
- 底层批次按现有 FIFO 顺序从来源库存中分配调拨数量。无论全部还是部分移动，都不修改原批次的历史库位：每段实际移动量在目标库位创建带 `sourceBatchId` 的调拨子批次，继承原品种、规格、供应商、品牌、单价、原始入库引用和追溯信息；目标“品种 + 规格 + 库位”库存条目不存在时在同一事务创建，存在时归并展示。这样部分调拨和多次调拨都不会丢失采购来源，之后的申领、归还和再次调拨仍可追溯到实际所在批次。
- 同一事务必须写入不可编辑、不可删除的调拨主记录和批次分配明细，原子减少来源批次/库存条目账面数量、增加目标批次/库存条目账面数量，并生成关联同一调拨 ID 的 `TRANSFER_OUT`、`TRANSFER_IN` 两组只追加流水；每条流水保存各自变动前后数量，全部来源减少量之和必须等于全部目标增加量。调拨前后品种级账面总量不变，任一库存、批次、流水、调拨记录或操作日志写入失败时全部回滚。
- 写接口必须携带稳定幂等键并复用主 PRD §3.3 的请求指纹与结果引用；同一幂等键重试返回原调拨结果，不得重复移库。成功响应至少返回调拨 ID、来源/目标库存条目 ID、数量及成对流水的最小引用；权限不足、输入非法、库存不足/已变化和未知异常继续使用主 PRD §9.5 的统一错误结构，不向前端暴露 SQL、锁或内部批次实现细节。
- 调拨完成后不允许编辑、软删除、硬删除或“回滚”原记录。确需纠正误调拨时，从当前实际所在库存条目重新发起一笔反向调拨，并可在备注中引用原调拨编号；只有当前仍有足够可用库存时才能成功。调拨记录可按品种、规格、来源库位、目标库位、操作者和时间筛选，默认按时间倒序；详情展示批次分配与成对流水，导出仍遵循主 PRD §10.3 的“导出所有 / 导出已筛选”。

## 7. 消耗品申领

**普通申领**

- 员工从申领目录选择品种和库存条目，填写数量和用途后提交申领清单；申领目录默认展示全部有可用库存的库存条目，可按分类筛选；一张清单可包含多种物品，同一库存条目只能出现一次。
- 员工可查看、取消本人待审批清单并查看处理结果。
- 审批人对整张清单批准或驳回（驳回必填原因）；批准即出库并生成库存流水，借还类物品同时生成借还记录。
- 申领额度、同时持有上限按 §5 在提交时占用，库存可用量同步占用；审批时校验占用记录仍完整有效并原子转为正式使用量/持有量和库存扣减，不按当前额度配置重复计算。清单历史、审批、额度占用和库存变更可相互追溯；已出库清单不能任意回滚。
- **历史记录**：本人历史随"消耗品申领"权限隐含提供；范围历史由"消耗品申领历史记录"权限（部门/公司）提供。

**代交申领**

- 持有"代交申领"功能（数据范围部门/公司）者可为范围内的一名或多名在职受领人创建代领清单；不能选择自己、不能重复选择同一人。
- 代领使用“受领人名单 + 一张共享物品清单”的结构；每种物品只填写清单总数量，不按受领人分摊，也不要求说明备用数量最终交给谁。受领人名单用于代领对象范围校验、审批数据范围和历史追溯，不建立“某件/某数量物品属于某位受领人”的关系。
- 代领清单由发起人统一提交、跟踪、取消；审批人一次审批整张清单，不按受领人或物品拆分。库存占用和出库只按共享清单的总数量计算一次，不得按受领人数重复乘算。
- 代领不受发起人或任何受领人的周期申领上限、同时持有上限限制，也不计入任何人的已申领数量或持有数量；仅校验数量为正、库存可用量、受领人范围和其它清单有效性。即使清单包含借还类物品，批准后也只形成与本代领清单关联的待归还数量，不占用任何人的个人持有额度。
- 受领人在"我的借还"中只读查看自己被列入受领人名单的整张共享清单，界面明确标记“代领共享清单、不计个人持有”，不得把清单数量展示成其个人领取数量；正常情况下取消、归还及其它变更只能由发起人完成，发起人已注销时按 §8 允许持有“消耗品审批”的人员直接结清，不把处置责任转给任一受领人。
- 代领采用**一次性整单结清**，不允许多次部分归还。发起人只能在不存在待处理结清申请时，对共享清单中全部未结清的借还类数量一次填写处理方式：正常归还、遗失或损坏；每种物品各处理方式数量之和必须等于该物品全部未结清数量，不能只提交其中一部分。待审批期间整张清单锁定，不得再发起另一结清申请；驳回或取消后可重新提交一张覆盖全部未结清数量的新结清单。
- 代领结清的正常归还、遗失和损坏均由统一的“消耗品审批”处理。批准时在同一事务一次完成全部回库、核销、库存流水和清单结清，任一部分失败则全部不生效；驳回时全部维持未结清。
- 代领历史保留发起人、受领人名单、共享物品清单、审批和归还信息；代领物品由发起人统一跟踪和发起归还，受领人及发起人均不被记录为这些物品的个人借用人。

## 8. 借还、归还与核销

- 普通申领中的借还类物品批准出库时生成个人借还记录（借用人、物品、数量、出库时间、到期时间、已归还、已核销）；到期时间 = 出库时间 + 品种的归还期限。代领共享清单中的借还类物品改为生成清单级代领借还记录，不设置个人借用人、不占用个人持有额度，但同样记录数量、出库时间、到期时间、已归还和已核销并要求结清。
- **我的借还**：查看本人借出、未结清、逾期、归还申请和核销申请；本人未结清借还行可发起归还与核销申请；含"借还 / 历史记录"两个视图，本人历史随权限隐含。
- **发起归还**：对未结清数量部分或全部归还，提交待确认申请（待确认数量仍计入持有量）；由持有“消耗品审批”的审批人确认，确认后库存回到原批次与库存条目（恢复可用库存），驳回需说明原因。
- **遗失/损坏核销**：填写类型、数量和原因，经持有“消耗品审批”的审批人通过后从持有量结清，不回库。
- 个人归还与核销提交时必须在同一事务锁定对应个人借还记录并占用待处理数量：`可申请处理数量 = 未结清数量 − 待审批归还占用 − 待审批核销占用`。本次申请不得超过可申请处理数量；批准时把占用转换为已归还或已核销，驳回或发起人取消时释放。并发归还与核销不能使“已归还 + 已核销 + 待处理占用”超过原借出数量。
- **已注销员工直接归还/核销**：持有“消耗品审批”的审批人可在审批中心的“注销员工借还处置”功能中，直接处理其数据范围按主 PRD §3.2 规则覆盖的已注销员工个人借还记录；部门范围使用借出时保存的借用人部门快照，公司范围可处理全部。操作者选择正常归还或遗失/损坏核销并填写正整数数量；核销必须选择遗失/损坏类型并填写原因，归还可填写备注。该操作不创建归还/核销申请，不进入待审批状态，也不需要再次审批，确认成功即为最终业务结果。
- 直接处置接口必须在同一数据库事务中重新校验“消耗品审批”权限和数据范围、借用人仍处于注销状态、借还记录归属与可处理数量，并锁定目标个人借还记录。`可直接处理数量 = 未结清数量 − 待审批归还占用 − 待审批核销占用`；注销前已经提交的待审批归还/核销申请继续按 backstage PRD §3 的注销规则正常审批，其占用数量不能被直接处置重复处理。借用人在确认前已恢复账号、数量超限、记录已结清或并发状态变化时整次拒绝，不产生部分库存或结清结果。
- 直接归还在事务中增加原批次与库存条目的账面库存并写入库存流水；直接核销只减少个人未结清持有量，不回库。两者都必须支持幂等键，并写入不可删除的管理员直接处置记录，保留借用人、借出时部门快照、处理方式、数量、核销类型/原因或归还备注、处理人、处理时间和关联库存流水，再按主 PRD §3.3 记录操作日志；任一写入失败全部回滚。
- **已注销代交人共享清单直接结清**：代领共享清单的发起人已注销、清单仍有未结清借还数量且不存在待审批结清申请时，持有“消耗品审批”且数据范围按主 PRD §3.2 覆盖原受领人名单全部部门快照的人员，可在同一“注销员工借还处置”功能中直接完成一次性整单结清。处理表单与 §7 一致，必须覆盖全部未结清物品，并使每种物品的正常归还、遗失、损坏数量之和等于该物品未结清数量；确认后不创建结清申请、不进入待审批，直接在一个事务中完成全部回库、核销、库存流水、清单结清、管理员直接处置记录和操作日志，任一行失败整单回滚。发起人在确认前已恢复、已有待审批结清申请或清单状态变化时拒绝直接处置；注销前已经提交的结清申请继续正常审批，不能与直接结清并行。
- **代领一次性结清**：入口在发起人的代交申领清单中（见 §7），必须覆盖全部未结清数量，统一由“消耗品审批”处理；待审批期间对整张代领借还记录形成结清占用，驳回或取消后释放。
- **借还历史记录**：由"借还历史记录"权限（部门/公司）提供，管理员按物品、记录类型（个人借还/代领借还）、借用人或代交人、受领人、部门、结清状态、逾期情况查询借还、归还与核销记录（只读追溯）。
- 未结清 = 借出 − 已归还 − 已核销；到期后仍允许归还，逾期只提示不阻止；归还期限调整只影响之后新借出的物品；借还、归还、核销记录均保留审计历史。

## 9. 审批中心（asset）

- 统一待办，支持按"申请类型"筛选：**库存入库、库存变更、消耗品申领、归还、遗失/损坏核销、代领结清**六类在同一审批中心统一展示，切换类型即按该类型独立分页查询。
- 六类申请全部由唯一的“消耗品审批”功能控制，不再拆分入库、库存变更、申领、归还或核销审批权限。该功能的数据范围为部门/公司两档：公司范围可查看和处理全部六类；部门范围只可处理数据范围覆盖的消耗品申领、归还、遗失/损坏核销和代领结清，不显示库存入库和库存变更类型。处理时仍按主 PRD §3.2 重新校验整张申请。
- 审批中心另提供“注销员工借还处置”功能，仅向持有“消耗品审批”的用户开放，含“待处置 / 处置记录”两个视图：待处置按 §8 列出其数据范围内已注销员工尚未结清的个人借还记录，以及发起人已注销且可直接整单结清的代领共享清单；处置记录按处理时间倒序显示其当前数据范围内的管理员直接处置结果及关联库存流水摘要，可按记录类型、借用人/代交人、处理方式、处理人和时间筛选并查看详情，不额外要求“借还历史记录”或“消耗品库存管理”权限。该功能属于审批功能附带的业务处置入口，但操作本身不是审批申请，不计入六类待办数量，也不出现在待处理/已处理审批列表中；另有相应权限者仍可从借还历史和库存流水交叉查询同一结果。
- 支持"待处理 / 已处理 / 具体状态"筛选；支持按关键字、申请人姓名、审批人姓名搜索；导出遵循主 PRD §10.3，仅提供当前权限范围内的“导出所有 / 导出已筛选”，不提供当前页导出。
- 六类待办不展示审批截止时间；页面展示提交时间和已等待时长。申请保持待审批，直至审批人批准/驳回、提交人/代交人取消或按主 PRD §3.2 超时自动取消；相关库存、额度、待处理数量和结清占用在待审批期间持续保留，并在驳回、取消或超时自动取消时按业务规则释放。
- 资产审批中心承载六类审批待办处理、审批历史，以及 §8 明确规定的注销员工借还直接处置；不汇集普通员工本人的申请记录。本人记录仍由各功能"历史记录"视图按授权数据范围承载，不设独立的个人记录汇集页。

## 10. 系统首页

- 资产系统首页本期只展示欢迎信息与按权限过滤的常用功能快捷入口，不实现资产、库存、待审批等统计型仪表盘。

## 11. 二维码

- 二维码扫码需登录后生效：扫码打开对应入口（资产详情/申领），未登录先进入登录页，登录后跳转对应页面。
- 每个有库存的库存条目提供二维码，扫码进入对应申领入口；固定资产提供扫码查看入口；另提供长期有效的申领目录二维码（不绑定具体品种或批次）。每个二维码使用独立、至少 128 位随机性的公开不透明标识，不编码数据库自增 ID、业务编号或其它可枚举内部标识；数据库保存该公开标识原值并建立唯一索引，同时保存目标类型/目标标识，以便重新展示和打印同一张有效二维码。该标识不是登录凭证或授权秘密，扫码后仍由服务端解析并执行登录、权限和状态校验，二维码本身不授予任何权限；解析接口需要限流，日志不得记录完整扫码 URL。
- 二维码 URL 使用前端固定扫码入口并把公开标识放在 URL fragment 中，例如 `/scan#<publicId>`，使 fragment 不进入 Nginx/HTTP 访问日志和 `Referer`；扫码页从 fragment 读取后通过受保护的解析接口请求体提交，并立即从地址栏移除。未登录时只允许在当前标签页的内存或 `sessionStorage` 暂存该公开标识以完成登录后跳转，解析完成、失败或标签页关闭后清除，不写入 `localStorage`、Cookie 或前端分析日志。后端仍不得把请求体中的完整公开标识写入普通日志。
- 扫码解析成功后仍按当前登录用户的功能权限、数据范围、目标状态和库存状态进行校验；未登录先登录，登录后恢复跳转。无权限、目标已删除、二维码无效或库存条目当前不可申领时，不泄露目标的内部详情。
- 二维码管理归属：固定资产二维码归“固定资产维护”（见 §4），库存条目二维码与长期申领目录二维码归“消耗品库存管理”（见 §5）。二维码支持三种管理动作：“停用”使当前二维码暂时无效；“恢复”使同一张已打印二维码重新有效；“作废并重新生成”创建新的随机标识并使旧标识永久失效，旧二维码之后不能恢复。二维码状态变更和重新生成记录操作日志；重新生成只更换扫码入口标识，不修改资产或库存业务数据。

## 12. 资产配置（系统内页面）

- 权限：asset 功能"资产配置"。
- 运行参数：扫码入口地址、申领上限重置日（默认每月 1 号，可设 1～28 号以保证每个自然月都存在该日；按 §5 统一决定月/季/年上限的重置时点）等；本期不提供消耗品审批期限配置。
- 业务选项：资产分类、消耗品分类、单位、库存变更类型（仅表示意外扣减原因，不带增减方向）、供应商、品牌、规格、资产规格与型号。
- 受控选项只能使用已启用值；停用值不能自动恢复；历史数据引用停用选项时保留原值展示。资产分类、消耗品分类和各业务字典项均按主 PRD §2.6 提供批量硬删除，仅未被业务或历史记录引用的项可删除，任一项不可删除则整批回滚。
