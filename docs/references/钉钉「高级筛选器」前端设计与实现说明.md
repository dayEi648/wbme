# 钉钉「高级筛选器」前端设计与实现说明

## 一、功能定位与适用场景

### 1\.1 核心定位

高级筛选器是钉钉体系内表格类页面的通用复杂筛选业务组件，区别于表头单列筛选、平铺式基础筛选，它支持**多字段自由组合、多逻辑关系嵌套、按字段类型匹配比较规则**的精细化数据过滤，专门满足低频但逻辑复杂的业务筛选需求，是基础筛选能力的补充升级。

### 1\.2 覆盖场景

该组件为钉钉全业务线的通用能力，主要落地在以下场景：

- 钉钉原生电子表格、多维表格（AI 表格）的数据筛选

- 宜搭表单数据管理页、报表仪表盘的条件过滤

- 项目管理（Teambition）、审批、CRM 等业务模块的列表 / 表格页

- 支持自定义字段、需要多维度组合逻辑的 B 端数据列表场景

## 二、整体组件架构

钉钉高级筛选器基于 Ding Design 基础组件体系构建，采用**三层嵌套架构**，与后端筛选 API 的三层模型（Filter → FilterCriteria → FilterCondition）完全对齐，前端组件分层如下：

|架构层级|组件模块|核心职责|依赖的基础组件|
|---|---|---|---|
|第一层|高级筛选容器|承载整个筛选面板，控制显隐、提交 / 重置全局操作|Modal（PC 端弹窗）/ Drawer（移动端抽屉）|
|第二层|条件逻辑组|管理一组条件的逻辑关系（AND/OR），支持嵌套子组|自定义逻辑容器 \+ 逻辑切换下拉框|
|第三层|单条件行|单个筛选条件的完整交互：字段选择 \+ 运算符选择 \+ 值输入|由 3 个动态表单控件组合而成|

### 架构核心特点

- 前后端模型一一对应，前端数据结构可直接序列化对接筛选接口，无需额外转换

- 条件组最多支持 2 层嵌套，在灵活性和易用性之间做了平衡

- 单条件行的控件完全由字段类型动态驱动，无需为每个业务字段单独开发

## 三、核心组件详细说明

### 3\.1 外层容器组件

#### 组件形态

- **PC 端**：居中模态弹窗，固定宽度，条件内容区支持纵向滚动

- **移动端**：底部抽屉，全屏高度，适配触控操作的大尺寸控件

- 标题栏：显示「高级筛选」标题，右侧提供关闭按钮

#### 底部操作区

- **重置按钮**：清空所有条件，恢复为 1 条空条件行的初始状态

- **取消按钮**：放弃本次修改，关闭弹窗，不改变当前生效的筛选

- **确定 / 应用按钮**：校验所有条件合法性，将筛选条件同步到表格，关闭弹窗

- 扩展按钮：可选「保存为筛选视图」，将当前条件配置存储为可复用的个人视图

### 3\.2 条件逻辑组组件

#### 核心功能

- 统一管理组内所有条件 / 子组的逻辑关系，提供「且（AND）」「或（OR）」切换下拉

- 提供「添加条件」「添加条件组」两个操作入口

- 嵌套组通过缩进、分隔线做视觉区分，明确逻辑范围边界

#### 交互规则

- 每个逻辑组内只能使用同一种逻辑关系（全 AND 或全 OR），不可混合

- 根逻辑组默认逻辑为「且」，默认包含 1 条空条件行

- 嵌套层级最多开放 2 层，避免逻辑过于复杂提升用户理解成本

- 当组内只剩 1 条条件时，删除条件会保留空行，不删除逻辑组本身

### 3\.3 单条件行组件

单条件行是高级筛选的最小交互单元，固定为 \\*\\*「字段选择器 → 运算符选择器 → 值输入控件」\\*\\* 的三段式结构，三个控件强联动变化。

#### 1\. 字段选择器

- 组件类型：带搜索功能的下拉选择框（SearchSelect）

- 数据源：当前表格的全部可筛选字段，包含系统预置字段和用户自定义字段

- 展示规则：显示字段的可读名称，实际值为字段唯一标识（fieldId）；字段按类型分组展示

- 联动作用：选中字段后，自动刷新运算符下拉选项，并切换值输入控件的类型

#### 2\. 运算符选择器

- 组件类型：下拉选择框（Select）

- 选项规则：**根据字段类型动态适配可选运算符**，不同字段类型对应不同的比较逻辑

- 特殊处理：选中「为空」「不为空」类运算符时，值输入控件自动禁用，无需用户填写

#### 3\. 值输入控件

- 组件类型：完全动态渲染，根据字段类型和运算符自动切换对应表单控件

- 字段类型与控件映射：

    - 文本字段：单行输入框，支持关键词输入

    - 数字字段：数字输入框；「介于」运算符时自动渲染双输入框

    - 日期字段：日期选择器；范围 / 区间运算符时渲染日期区间选择器

    - 单选 / 多选字段：下拉选择框 / 多选框，选项为字段的枚举值

    - 人员 / 部门字段：人员选择器 / 部门选择器

    - 级联字段：级联选择器

## 四、筛选运算体系

### 4\.1 字段类型与运算符映射

钉钉高级筛选针对不同字段类型提供差异化的比较运算符，完整映射关系如下：

|字段类型|支持的比较运算符|
|---|---|
|文本类（单行文本、多行文本）|等于、不等于、包含、不包含、开头是、结尾是、为空、不为空|
|数字类（数值、评分）|等于、不等于、大于、小于、大于等于、小于等于、介于、为空、不为空|
|日期类（日期、创建时间等）|等于、不等于、早于、晚于、介于、今天、本周、本月、过去 7 天、过去 30 天、为空、不为空|
|单选类（单选、下拉单选）|等于、不等于、为空、不为空|
|多选类（复选、下拉多选）|包含、不包含、为空、不为空|
|人员 / 部门类|等于、不等于、属于、不属于、为空、不为空|

### 4\.2 逻辑组合规则

1. **组内统一逻辑**：同一条件组内的所有条件，遵循同一种逻辑关系（且 / 或）

2. **父子组继承逻辑**：父组的逻辑关系作用于其下所有子条件和子组

3. **典型嵌套示例**：根组为「且」，包含 2 个普通条件 \+ 1 个「或」子组，逻辑等价于：`条件1 AND 条件2 AND (条件3 OR 条件4)`

## 五、完整交互流程

### 5\.1 入口与打开

- 入口位置：表格工具栏的「筛选」按钮旁的「高级筛选」入口，或基础筛选面板底部的「高级模式」切换按钮

- 打开行为：弹出高级筛选弹窗，自动回显当前已生效的所有筛选条件

- 双向联动：表头单列筛选的条件会自动同步到高级筛选面板，修改高级筛选后也会同步回表头筛选状态

### 5\.2 条件编辑流程

1. 点击字段下拉框，搜索或选择目标筛选字段

2. 系统自动加载该字段支持的运算符列表，默认选中最常用的「等于」

3. 系统自动渲染对应类型的值输入控件，用户输入或选择条件值

4. 点击「添加条件」新增一行条件，重复上述操作

5. 如需组合逻辑，点击「添加条件组」创建嵌套子组，切换组内逻辑关系

6. 单条条件右侧的删除图标，可删除当前条件行

### 5\.3 提交与生效

- 点击「确定」：先校验所有条件的合法性（必填值是否填写、格式是否正确），校验通过后关闭弹窗，表格数据实时刷新

- 筛选生效后，表格顶部显示筛选条件标签栏，每个条件以标签形式展示，支持单个删除；点击标签区域可重新打开高级筛选面板编辑

- 点击「重置」：清空所有条件行，恢复为 1 条空条件的初始状态

## 六、前端数据模型

高级筛选的前端状态采用树形结构存储，与后端筛选 API 的参数结构完全对齐，可直接序列化后提交。

### 基础数据结构

```Plain Text
筛选根组
├── operator: "and" | "or"   // 组内逻辑关系
└── conditions: Array         // 组内元素，可为单条件或子组
    ├── 单条件对象
    │   ├── field: string    // 字段唯一标识
    │   ├── fieldType: string // 字段类型（前端渲染用，提交后端可省略）
    │   ├── operator: string // 比较运算符
    │   └── value: any       // 条件值，类型随字段变化
    └── 子组对象（嵌套）
        ├── operator: "and" | "or"
        └── conditions: Array
```

### 设计说明

- 统一的树形结构同时支持平级多条件和嵌套条件组，无需维护两套数据模型

- 值的格式严格遵循字段类型规范：日期为标准格式字符串，多选值为数组格式，空值运算符对应 null

- 条件的新增、删除、修改直接操作该树形数据，视图层由数据驱动渲染

## 七、扩展能力与边界特性

### 7\.1 筛选视图能力

- 支持将当前配置的筛选条件保存为「筛选视图」，存储名称和完整条件配置

- 每个工作表最多支持创建 20 个筛选视图，用户可在视图列表间一键切换

- 筛选视图为个人化配置，不同用户的视图互不影响

### 7\.2 跨端一致性

- PC 端与移动端共用同一套数据模型和运算逻辑

- 交互形态适配端特性：PC 端弹窗多列紧凑布局，移动端抽屉单列布局

- 字段、运算符、组合规则完全一致，保障跨设备体验统一

### 7\.3 体验优化点

- 字段列表支持虚拟滚动，应对上百个自定义字段的长列表场景

- 条件变更不实时触发查询，点击「确定」后统一提交，减少无效请求

- 常用字段置顶、最近使用字段记忆，提升字段选择效率
